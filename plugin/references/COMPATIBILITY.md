# Runtime boundaries

The 18 inherited workflow skills retain the prototype's engineering intent;
four entrypoints add portable setup, job control, design routing and reviewed
learning. Bundled examples are not qualified project policy. Their commands,
framework versions and MCP tool names need verification against the project.

Use the installed `cep --help` interface. Skills never authorize missing commands
or replace protected acceptance. Native custom agents inherit parent permissions;
the bundled reviewer personas are not independent isolation. Run mandatory
acceptance review in a separate restricted root session.
Failed preflight prohibits worker launch. In particular, successful filesystem
and network probes do not compensate for a failed descendant-lifecycle probe.
Retain the failure; do not bypass sandboxing or choose an unapproved fallback.

The hook-free portable manifest and Codex compatibility fallback follow
https://developers.openai.com/plugins/build/plugins. Project activation uses the
documented plugin-name@marketplace-name key. Agent assets are selectively copied
to `.codex/agents/`; plugin installation does not implicitly register TOML agents.

Runtime, local Codex authentication and optional MCP connections are prerequisites
supplied by each user. No account connections, personal configuration, hook trust,
global permissions or service credentials are bundled. UI and reviewed-memory
procedures remain required scope; their live qualification belongs to later
slices and must not be inferred from plugin discovery.
